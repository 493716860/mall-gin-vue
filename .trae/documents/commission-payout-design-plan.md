# 分销佣金真实提现设计补充计划

## Summary

补全商城架构中的分销奖励账户与真实提现设计，明确佣金不作为积分，也不设计成可充值、转账或用于消费的通用钱包。使用独立的佣金资金账本记录平台对推广员的应付金额，并通过提现申请及出款 Provider 将可提现佣金真实支付给推广员。

本次仅更新架构文档，不实现账户、提现 API、支付通道或代码。

## Current State Analysis

- `/workspace/docs/architecture.md` 已定义 `commission_ledger`、`commission_payout_request`，并说明确认收货后佣金可结算、退款通过冲正处理。
- 该文档仍将提现资格、实际打款通道和审批流程列为待定；未明确佣金账户与积分/储值账户的边界、冻结状态、出款失败处理和提现后退款处理。
- `/workspace/.trae/documents/wechat-mall-architecture-plan.md` 是此前的实施计划，不是分销提现详细设计；本次不修改它。

## Proposed Changes

- 更新 `/workspace/docs/architecture.md`：
  - 在架构决策、目录/模块职责和逻辑数据模型中明确分销模块提供独立的佣金资金账本/佣金账户；与会员积分和储值账户分离。
  - 说明此账户仅核算商城佣金应付款，不支持充值、用户间转账或商城消费，不描述为通用电子钱包；可提现金额须经独立提现流程出款。
  - 将佣金余额定义为追加式账本的汇总/投影，分别核算待结算、冻结、可提现、提现中、已提现及人工追偿处理金额；余额变更均能关联订单、退款或提现业务单。
  - 补充提现流程与状态转换：用户从已启用渠道中选择微信商户出款或银行转账；小额申请在通道可用且风控通过时自动审批/出款，大额申请转人工审核；银行人工转账须由财务登记结果/凭证。限额、最低提现额和冻结天数均为后台配置项，具体数值留待运营确认。
  - 补充确认收货后的可提现保护期：佣金先进入冻结状态，在配置的冻结期届满且无阻断性售后后释放为可提现；保留冻结起止时间和所用规则版本。
  - 通过出款 Provider 隔离自动微信出款与人工银行出款。实际微信商户出款能力、资质、实名要求和合规条件在接入前核实，不承诺未核实的接口资格。
  - 优先由出款通道完成实名/收款账户验证；商城仅保存通道令牌、脱敏展示信息和必要审计记录，不保留完整收款资料，除非合规与产品评估另行批准。
  - 定义提现幂等、余额预占/锁定、通道处理中、成功、失败、撤销和重试/对账语义；出款失败或撤销需释放被锁定金额，重复回调不得重复付款或扣账。
  - 按已选政策，佣金已提现后发生退款时只自动登记异常与风险冻结，由财务逐案决定后续冲抵或追偿；系统不自动扣款或静默形成负余额。
  - 增补审核权限、操作审计、提现风控、对账、失败告警、测试策略、验收项及上线前需确认的费率/限额/税务合规事项。

## Assumptions & Decisions

- 奖励采用现金计价的佣金账本/佣金账户，不发积分替代可提现佣金；积分仍作为独立会员权益。
- 账户是商城内部应付佣金的业务子账，不是可储值、可转账或可消费的通用钱包。
- 出款适配微信商户出款和银行转账双通道；推广员可选择当前已启用且其收款资料验证通过的渠道。
- 小额自动、大额人工审核；具体金额阈值、单次/每日限额和最低提现额由后台配置，实施前由运营/财务确认。
- 确认收货后进入可配置冻结期，期满且无相关售后阻断后才可提现；冻结天数需由业务确认。
- 实名及收款账户信息优先由通道托管/验证，商城最小化保存。
- 已提现后退款仅人工处理；系统记录异常、冻结待处理风险账户并审计人工处置结果。
- 本次产出仅为架构文档，不调用或验证微信/银行真实支付接口。
