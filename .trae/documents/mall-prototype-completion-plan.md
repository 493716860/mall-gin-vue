# 商城原型完整度评估与补全计划

## Summary

当前 `mall-commerce-closed-loop-v3` 是覆盖面较广的本地交互原型，不是可生产运营的商城。已有商品 SPU/SKU 管理与上下架、购物车和模拟支付、订单履约、配送模板、评价晒图与商家回复、会员等级折扣，以及分销申请、推荐关系、佣金账本和提现审核等主要页面。

本计划仅补齐可演示的原型业务闭环。首期重点为：商品售卖现有功能回归验收、退货退款、可执行的会员权益、一级直推分佣。真实支付/退款、快递平台 API、服务端数据库、鉴权及真实打款不在本轮范围，仍是生产上线前置项。

## Current State Analysis

- `data.js`、`MallData.read/write` 以同源 `localStorage` 保存状态；前后台共享仅限本浏览器演示数据。
- 商品后台已支持 SPU/SKU 编辑、库存和上下架；小程序已有商品详情、选规格、购物车、结算及模拟支付。
- 物流已有省份配送模板和商品关联；后台可人工录入承运商/运单，用户端查看演示轨迹。真实物流查询和电子面单尚未接入。
- 售后目前以退款申请和后台审核为主，缺少按商品/数量发起退货、买家退货物流、后台验收后退款及退货库存恢复。
- 评价已有文字/星级/图片和商家回复；本计划按用户选择不扩展评价举报/审核/隐藏。
- 会员门槛和等级折扣可配置，但积分倍率、SKU 会员价及生日券尚未形成可执行闭环；权益文案可能与实际效果不一致。
- 分销当前演示支持最多三级；首触关系、结算账本等已有模型，但首期需收敛为一级，并清理演示数据中佣金、订单、关系快照不一致的样例。
- 支付、退款、物流和提现均为本地模拟；因此本轮验收目标是前后台状态与金额一致，不代表真实资金或权限安全。

## Proposed Changes

### 1. 退货退款闭环

- `data.js`：为售后单补充订单明细/SKU/申请数量、商品实付退款额、原运费处理、退货物流、验收记录和状态时间；读取旧 `localStorage` 时提供默认值，不覆盖已有订单。
- `commerce.js`：按订单商品和可退数量校验申请，按优惠分摊后的商品实付净额计算退款上限；未发货申请走退款审核，已发货申请走“审核通过 → 用户填写退货物流 → 后台确认收货/验货 → 退款完成”。重复申请和重复审核须幂等；退货库存只在后台验收通过时恢复；退款按比例冲减对应一级佣金，已提现不足冲回时保留异常账目。
- 退货运费按原因展示：质量/错发等商家责任由商家承担；无理由退货由买家承担。整单因商家责任退货时退回原订单运费；无理由退货不退原运费。以上为原型默认规则。
- `mini-commerce.js`、`mini.js`：增加按商品/数量选择、原因与描述、退款预估、退货物流填写及售后进度页；不做换货。
- `commerce-admin.js`：补齐售后审核、退货物流查看、验收确认和退款结果操作；不同售后状态提供合法操作，避免售后处理中仍能重复发货或重复退款。

### 2. 会员权益落地

- `data.js`：会员等级增加可配置积分倍率；SKU 增加按会员等级设置的专享价映射；新增全会员统一生日券配置和逐年发放记录。
- `admin.js`：会员等级表单维护折扣、积分倍率及权益说明；商品 SKU 编辑维护会员专享价；会员配置选择一张现有优惠券作为统一生日券。
- `commerce.js`、`mini.js`：显式 SKU 会员价优先于等级折扣，两者不叠加；优惠券仍按当前结算规则应用。确认收货时按商品实付净额和会员积分倍率发积分。生日月首日发券，每个会员每年只发一次；静态原型在生日月首次运行时补发，使用发放记录防重复。
- 生日券使用现有优惠券类型/核销规则；未配置有效生日券时不发券并在后台显示配置提醒。

### 3. 一级推荐分成

- `data.js`：将 `distributionSettings.maxLevels` 和有效规则收敛为一级，保留既有推广等级首级比例：普通推广员 5%、银级 6%、金级 7%；修正或替换佣金与推荐关系不匹配的种子数据。
- `commerce.js`：沿用首次有效推荐绑定且不被后续分享覆盖；仅直接推荐人可得佣金，自购不计佣。按商品实付净额计佣、不含运费；支付后生成待确认账目，确认收货后冻结 7 天再转可提现；退款按商品退款比例冲正。所有创建、冻结、释放和冲正继续使用幂等键与规则版本快照。
- `distribution-admin.js`、`distribution-mini.js`：后台规则文案、层级展示、佣金/团队页面和提现说明统一为一级，不再展示无效的二级/三级收益。

### 4. 现有交易功能回归验收

- 保留商品管理、库存、购物车、模拟支付、地址运费模板、评价图片和回复等现有交互；补齐端到端验收场景，不重复建设已存在功能。
- 检查订单金额、商品 SKU 快照、库存、运费和佣金快照一致；审核售后时校验订单状态与剩余可退款数量。
- `app.css`：补充售后状态、退款明细、会员权益字段和一级佣金展示样式，沿用现有小程序与后台视觉体系。

## Assumptions & Decisions

- 目标为完整可点击的本地原型，所有数据继续保存在现有 `localStorage`；不接生产后端或第三方支付/物流/打款服务。
- 售后只做退款、退货退款，不做换货；退货必须录入承运商/运单并由后台验收后退款。
- 退款按商品明细和数量计算；会员折扣/优惠券影响可退商品净额，退货库存仅验收通过后恢复。退款运费按售后原因承担，采用上述默认规则。
- 推荐归因采用首次有效推荐、永久不覆盖；分销只奖励直接推荐人，沿用 5%/6%/7% 首级比例、商品实付净额基数、收货后冻结 7 天和退款比例冲正。
- SKU 专享价与等级折扣不叠加，SKU 专享价优先；全会员使用同一生日券，生日月首日发放、月底到期、每年一次。原型用生日月首次运行补发来模拟定时任务。
- 本轮不扩展评价举报/审核/隐藏，不实现真实支付、物流轨迹、退款通道或提现出款。

## Verification

- 迁移检查：旧版演示数据读取后不丢订单、商品、地址、评价、佣金和关系；缺省新字段可安全补齐。
- 商品销售回归：SPU/SKU 上下架、不同 SKU 库存、购物车结算、地址运费和支付后库存变动正确。
- 售后测试：未发货退款、已发货退货、部分数量退款、超额/重复申请拒绝、运单填写、验收后退款、不同责任原因运费、验收后库存恢复，以及佣金按比例冲正。
- 会员测试：不同等级折扣、SKU 专享价优先且不叠加、积分倍率、生日券只发一次/有效期/结算核销。
- 分销测试：首次有效推荐绑定、后续触点不覆盖、无推荐人/自购不计佣、5%/6%/7% 一级佣金、运费排除、7 天冻结释放、退款冲正和幂等。
- 执行所有修改 JS 的 `node --check`、`git diff --check`；在小程序和运营后台分别走完上述主链路并检查状态与金额展示。
- 生产化另立计划：服务端身份与权限、数据库事务/并发库存、真实支付/退款回调、物流与电子面单、定时任务、对账及审计。
