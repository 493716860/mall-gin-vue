# 微信小程序商城架构方案计划

## Summary

为全新仓库编写一份中文企业级架构方案，指导后续搭建单商户微信小程序商城。方案覆盖 Go/Gin 模块化单体后端、运营后台、微信小程序、基础设施、主要业务模块、分销规则、关键数据与流程、API 边界、测试和部署。

本阶段只交付架构设计文档，不创建可运行代码、前端工程、数据库迁移、Docker 配置或第三方服务接入。

## Current State Analysis

- `/workspace` 当前只有 Git 元数据和一个无扩展名的 `demo` 文本文件；没有 Go 模块、应用代码、前后端工程或现存架构文档。
- 因此文档将作为新项目的基线设计，不依赖现有实现，也不覆盖或改写 `demo`。
- 已确认项目为单商户商城；运营后台与小程序均纳入架构范围，但本阶段不实现前端。

  - 目标、非目标、技术栈与架构决策。
  - Go 后端及两个前端的建议目录树，按业务模块归类；区分领域业务代码、公共基础设施、应用入口、迁移/配置和部署资源。
  - 模块职责与依赖方向，避免跨模块直接访问存储实现；列出用户/会员、商品/库存、购物车/结算、订单/支付、售后/退款、履约/物流、客服、营销、分销/佣金、后台账号/RBAC、审计等模块。
  - MySQL、Redis、RabbitMQ、腾讯云 COS、微信支付、微信原生客服及可替换物流 Provider 的职责和边界。
  - 关键数据实体/关系与 API 分面：管理端 API、小程序 API、认证、错误结构、分页、幂等及权限约束。
  - 关键业务流程：微信登录、下单与库存、支付通知、退款与售后、优惠计算、物流履约、客服入口和异步事件处理。
  - 分销设计：申请审核；推广关系首次绑定且普通推广链接不覆盖；最多三级可配置；等级晋升阈值由后台按累计销售额、拉新人数、自购金额配置，并支持 AND/OR 组合与周期评估；佣金规则可按等级/层级配置；基数为实付商品净额扣除退款、不含运费；确认收货后结算，退款按实际退款冲减；说明幂等、冻结、冲正与审计。
  - 运维与质量要求：Docker Compose 开发部署边界、配置与密钥管理、日志/指标/追踪、健康检查、迁移、备份、权限审计及分层测试策略。
  - 分阶段实施顺序、验收清单、重要风险与需要在编码前确认的供应商细节。

## Assumptions & Decisions

- 后端：Go + Gin，GORM，MySQL + Redis + RabbitMQ。
- 架构：单商户、模块化单体；用清晰接口隔离模块，暂不拆微服务。
- 前端：运营后台 Vue3；小程序 Vue3 + uni-app。
- 部署：以 Docker Compose 作为首期本地开发及单机部署方案。
- 集成：微信登录、微信支付、微信原生客服；对象存储优先腾讯云 COS；物流集成通过 Provider 接口隔离，当前不锁定物流厂商。
- 后台账号采用账号登录 + RBAC，并记录关键操作审计；小程序用户采用微信登录。
- 营销架构纳入优惠券/满减、秒杀、拼团、积分/储值。
- 本阶段不定义具体佣金百分比、等级阈值、营销数值、物流供应商或云环境参数；这些作为运营配置或后续实施确认项。
- 不实现代码或进行第三方网络接入；架构文档是本次唯一交付物。
