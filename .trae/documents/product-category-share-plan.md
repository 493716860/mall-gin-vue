# 商品分类与分销分享设计补充计划

## Summary

补全商城架构文档中的商品分类维护与小程序商品分享/分销归因设计。明确后台只维护一级、二级分类，商品挂二级分类；小程序用户可查看商品详情并分享到微信好友、朋友圈及客户端生成的分享海报。所有分享带可追踪来源码，但仅有效合作推广员的分享码可建立分销关系并参与既有分销佣金规则。

本次只更新架构文档，不实现前后端代码、OpenAPI 文件、微信分享接入或海报生成。

## Current State Analysis

- `/workspace/docs/architecture.md` 已有 `catalog` 模块和泛化的商品类目职责，但没有分类层级约束、后台分类管理或商品挂类规则。
- 文档说明小程序包含商品页面，也有推广关系首次绑定、最多三级分销及佣金账本，但没有微信好友/朋友圈分享、海报、分享码签发/验证和分享归因流程。
- 既有推广关系规则为首次绑定后普通推广链接不能覆盖；本次延续此规则，不改变已确认的归因优先级及佣金结算生命周期。
- 工作区 `.screenshots/` 图片按用户指示保持不动，不读取或修改。

## Proposed Changes

- 更新 `/workspace/docs/architecture.md`：
  - 扩展目录树和模块职责：后台商品分类 CRUD 归属 `catalog`；小程序分享展示由商品页面发起，分享令牌签发、推广资格判定和分销归因由 `distribution` 管理，不新增独立微服务。
  - 规定分类树恰为一级/二级，根分类不可再作为子分类；商品必须关联有效的二级叶子分类。补充父子关系校验、停用/删除保护（存在子类或商品引用时不允许直接删除）和后台权限审计。
  - 扩展逻辑数据模型，加入 `product_category`（父级、层级、状态、排序）和分享追踪所需记录；在订单分销快照保留来源 token/渠道及推广员归属，便于订单与佣金审计。
  - 描述小程序商品详情的三种分享入口：微信好友卡片、朋友圈分享及客户端 canvas 海报；海报包含商品信息和指向相同商品页/归因入口的小程序码。
  - 分享 token 使用不直接暴露用户 ID 的不可篡改/可撤销标识，关联分享者、商品/落地页、分享渠道和版本；普通用户与有效合作推广员都可生成来源追踪码。
  - 规定资格与归因：普通用户分享只记录来源分析，不绑定 `referral_relation`、不产生佣金；只有有效合作推广员的 token 可为尚未绑定推广关系的用户建立首次分销归属。已有归属不被后续分享覆盖；无效/撤销推广员、自我邀请和伪造 token 不建立关系。
  - 描述归因闭环：小程序接收分享 token 并请求服务端校验；服务端记录分享访问/转化；满足条件后首次绑定推广关系；下单时固化推广员和最多三级上级快照；支付、确认收货、冻结期及真实提现继续复用现有分销佣金逻辑。
  - 更新 API 边界和 OpenAPI 规划，说明后台分类管理、商品详情分享数据、分享码签发/解析以及归因入口由哪个模块负责；明确服务端重新验证合作资格和分享 token，不能相信客户端直接传入的推广员 ID/佣金字段。
  - 增补分享隐私、防刷、令牌撤销、重复访问/订单幂等以及分类变更约束。
  - 补充分类与分享/归因的测试和验收项；将具体商品分享文案、海报视觉规范留给产品设计阶段。

## Assumptions & Decisions

- “商品分析”按用户确认理解为商品详情浏览，不增加用户侧商品经营分析仪表盘。
- 分类固定两层；商品只能关联二级分类。
- 所有小程序用户都可分享商品，所有分享携带可追踪来源码；仅审核通过且仍有效的合作推广员分享码可建立分销归因并获佣。
- 普通用户分享码仅用于来源追踪，不建立关系，避免非合作账号占用首次分销归属。
- 继续采用既有的首次绑定策略：已有推广关系不可被后续普通分享码覆盖；合作推广关系和佣金继续遵循最多三级及现有费率/结算政策。
- 分享渠道为微信好友、朋友圈与客户端生成海报；海报由小程序客户端按统一模板绘制，不为每个用户/商品海报增加服务端图片存储。
- 分享 token 不对外暴露内部用户 ID；签名/校验、权限撤销及风险策略由服务端负责。
- 交付范围是更新 `/workspace/docs/architecture.md`，不修改前端、后端代码或 `.screenshots/` 内容。
