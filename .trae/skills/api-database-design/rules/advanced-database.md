# 高级 MySQL 数据模型规范（P0）
关系：按基数设计 1:1、1:N、N:M 中间表，显式说明关联键、删除/更新策略；是否使用物理外键由现有项目约定和事务需求决定。业务唯一性用唯一约束保证，不能只靠应用查询。逻辑删除与唯一索引冲突要用明确方案，不能假设 deleted_at 自动解决。快照表保存历史下单时点事实，流水表记录不可覆盖的变动来源，余额表只存可校验汇总；重要金额以整数分存储。状态字段定义合法枚举和转移；时间语义统一 UTC/精度。Migration 必须向前兼容地考虑新增列默认值、历史数据回填、索引创建、回滚或补救方案，已执行迁移不可修改。所有新表及字段中文 COMMENT。
