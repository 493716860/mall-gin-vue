# 示例订单创建事务 TX-ORDER-001
本例仅演示设计方法，非真实业务决策。假设：订单创建时写入待支付订单；SKU 数量上限 99；金额由服务端计算；库存预占由库存模块的同库事务操作完成（若真实系统采用其他模式，需重新设计）。
1. 认证用户、校验请求和 Idempotency-Key；以 user_id+key 建立幂等作用域，并计算请求指纹。
2. 事务内锁定/原子校验可售库存（库存表结构由库存模块设计）；获取可信商品价格快照；写订单及明细；执行库存预占；提交。
3. user_id+key 唯一冲突：同指纹返回原结果，不同指纹返回 409。处理并发唯一冲突时重新读取已提交记录；不可重复预占。
4. 任一事务内步骤失败回滚，订单及库存变动必须一起回滚。
5. 支付、通知等外部调用不得在长事务内执行；超时/支付竞态由独立状态机与补偿任务设计。
6. 数据不变量：订单应付金额=明细金额之和（此例无运费/优惠）；订单创建成功与库存预占一致；同一用户同一幂等键至多生成一笔订单。
7. 待确认：库存预占策略、限购、优惠叠加、支付超时、金额分摊、幂等保留期和退款规则。
