# 微信商城交互原型 V3 需求基线

> 状态：根据已确认的会话需求、现有 V3 原型和《微信小程序商城架构方案》重建。此文件是当前可追溯的需求基线，不是对已丢失原始文件的恢复副本。  
> 目标：定义小程序消费者端与运营后台的可点击演示范围及关键业务规则。V3 是本地仿真原型，不是可直接生产运营的商城系统。

## 1. 产品目标与范围

- 提供消费者小程序与运营后台的端到端交互原型，演示商品上架、浏览、购买、履约、评价、售后、会员权益和推广佣金闭环。
- 小程序与后台在同一浏览器环境中通过本地演示数据联动；页面交互、状态和金额展示需前后一致。
- 商品、订单、售后、物流、营销、会员及推广数据均为模拟数据，不连接生产数据库、微信支付、物流平台或真实打款通道。
- 本需求文档以原型已确认规则为准；生产架构和实施约束另见 `docs/architecture.md`。

## 2. 消费者小程序需求

### 2.1 首页与商品浏览

- 首页展示 Banner、分类/专区、营销入口、推荐商品和商品卡片。
- 支持按一级/二级分类浏览、筛选商品及进入商品详情。
- 商品详情应展示多张主图、标题、副标题、价格、原价、销量、库存、销量榜 TOP 10、规格、购买数量、配送地址及运费、评价、图文详情和推荐商品。
- 销量榜默认收起，可展开；榜单商品可点击进入对应商品详情。
- SKU 可包含多个规格维度。用户选择规格后，价格、会员价、库存、图片、标签和可购买状态同步变化。
- 商品分享支持微信好友链接、朋友圈链接和商品海报演示；链接携带商品详情及来源标识，可进入对应商品详情页。

### 2.2 购物车、地址与订单

- 购物车支持 SKU 规格变更、数量增减、移除、勾选和库存校验。
- 购物车显示商品金额、会员优惠、优惠券优惠、运费和应付金额；优惠明细默认收起，点击后展开。
- 收货地址提供独立二级页面，支持查看、添加、编辑、删除、选择默认地址和选择结算地址；定位能力仅作原型模拟或授权入口演示。
- 结算根据商品关联的配送模板、收货省份/地区和免邮门槛计算运费。
- 支持创建订单、模拟支付、订单列表与详情，以及待付款、待发货、待收货、已完成、已取消、已退款等状态展示。
- 订单详情展示商品/SKU、金额优惠拆分、收货信息、物流承运商、运单号和轨迹。
- 用户确认收货后订单完成，并触发积分奖励和推广佣金冻结流程。

### 2.3 评价与客服

- 已完成订单支持待评价入口及按商品提交评分、文字评价和图片。
- 商品详情显示评价、图片和商家回复；评价提交后可在前台查看。
- 运营后台支持查看评价和回复用户评价。本阶段不做评价举报、审核或隐藏工作流。
- 小程序提供全局客服入口、未读消息样式和消息页面；本地原型演示文字及图片/视频选择或发送交互，不代表已接入微信客服或真实消息服务。

### 2.4 会员、积分与个人中心

- 展示会员等级、升级条件、等级折扣、积分倍率、SKU 会员价和生日优惠券等权益。
- 积分页面为独立二级页面，展示积分余额、获取/使用记录及规则。
- SKU 会员价优先于等级折扣，两种价格优惠不叠加；无 SKU 会员价时才按等级折扣计算。
- 确认收货按商品实付净额和下单时的积分倍率发放积分。
- 生日优惠券使用统一模板，在会员生日月首日发放、月底到期，同一会员每年仅发放一次；静态原型在生日月首次运行时补发。
- 设置页聚合个人信息、账号与安全、协议与隐私入口；个人信息支持头像、姓名、手机号、性别、生日、地区、地址等演示字段。
- “爱宠档案”作为独立入口；可查看和维护宠物名称、生日、品种、年龄等演示资料。
- 安全设置展示更换手机号、登录密码、授权管理、协议/隐私文件、个人信息收集清单、安全中心、注销申请和实名认证信息更新入口。涉及真实验证或注销的能力仅作流程演示。

### 2.5 售后

- 用户可对符合条件的订单按商品和数量申请仅退款或退货退款，填写原因和说明，并查看退款预估及工单进度。
- 未发货订单走退款申请；已发货/已完成订单走退货退款。本阶段不做换货。
- 退货退款审核通过后，用户需提交承运商和退货运单号；商家签收并验收后，原型才完成退款。
- 验收通过后恢复对应 SKU 库存；验收不通过则记录失败状态，不自动完成退款。
- 商家责任原因（如质量问题、错发/漏发）由商家承担退货运费；其他原因由买家承担。整单商家责任退货退回原订单运费，无理由退货不退原运费。
- 退款需同步反映订单累计退款、积分冲回及佣金比例调整。

## 3. 运营后台需求

### 3.1 商品、分类与配送

- 商品以 SPU/SKU 管理，支持商品基础资料、主图/详情图、标题/卖点、分类、价格、库存、销量、状态、评价展示和商品关联推荐等演示字段。
- SKU 支持多规格组合、单独价格/原价/库存/图片/上下架状态及各会员等级专享价。
- 支持新建、编辑、上架、下架及列表筛选；商品仅允许关联有效二级分类。
- 分类结构为固定两级：一级分类下设二级分类，商品关联二级分类。
- 配送模板可配置基础运费、免邮门槛、省份/地区包邮与差异运费，并关联商品；消费者端结算使用同一模板规则。

### 3.2 订单、物流与售后

- 订单工作台支持查询、状态筛选、查看订单、关闭未支付订单和待发货订单发货。
- 发货录入承运商、运单号和物流节点；消费者端订单详情同步展示物流信息。
- 售后工作台支持审核退款/退货退款、查看商品数量和退款金额拆分、查看退货物流、确认退货验收及记录验收意见。
- 订单状态、售后状态、库存、积分和佣金需按合法状态转换联动，避免重复发货、退款或恢复库存。

### 3.3 评价、营销、会员与内容

- 评价管理支持筛选和查看用户评价、晒图、回复内容；商家回复在消费者端可见。本阶段不配置评价举报或审核。
- 营销中心支持优惠券、主题活动、秒杀和拼团的演示配置、启停与消费者端展示。
- 会员等级管理支持等级门槛、折扣和积分倍率配置。
- 商品 SKU 编辑支持按会员等级设置会员价；价格不得高于对应 SKU 正常售价。
- 会员后台配置所有会员共用的生日优惠券模板，并查看发放记录/数量。
- 后台提供 Banner/专区、协议与规则等内容维护入口，消费者端展示对应配置。

### 3.4 用户与分销运营

- 用户工作台展示用户资料、会员等级、积分、订单/消费摘要、分销身份和账号状态，并提供演示级状态维护。
- 分销后台至少包含推广员申请、推广员档案、推广关系、等级及佣金规则、佣金账本、提现、风险异常和操作审计页面。
- 推广员申请需经过后台审核；有效推广员可创建商品或商城分享链接，普通用户分享只用于来源分析。
- 推广关系列表可查看直接推荐关系；有权限的运营人员可基于理由纠正关系，并记录前后值和审计信息。
- 账本展示订单佣金快照、退款调整、冻结/释放、提现锁定及状态变化；提现审核、模拟出款、失败释放和异常处理均只在原型内模拟。
- 佣金不属于积分或储值，不支持充值、用户间转账或商城消费。

## 4. 已确认的核心业务规则

- **归因**：首次有效推广归属生效后不被后续分享覆盖；后台纠正必须有理由并留审计。
- **佣金层级**：V3 原型仅计算直接推荐人佣金，不计算二级及更高层级。
- **推广等级费率**：普通推广员 5%、银牌 6%、金牌 7%；订单保存当时推广员等级、比例、基数和规则版本快照。
- **计佣基数**：订单商品实付净额，扣除退款，不含运费；自购订单不产生佣金。
- **佣金结算**：支付后进入待确认；确认收货后冻结 7 天，再进入可提现状态。存在售后时按状态规则延迟释放或调整。
- **退款联动**：未出款佣金按商品退款比例冲减；已提现后发生退款时记录待人工处置异常，不自动扣款或静默产生负余额。
- **会员定价**：SKU 会员价优先于等级折扣，二者不叠加；优惠券按结算规则另行计算。
- **生日券**：全会员统一模板；生日月发放、月底到期、每会员每年一次。
- **退货验收**：退货运单由用户提交，商家验收通过后模拟退款并恢复对应库存。
- **演示边界**：支付、退款、物流轨迹、微信客服消息、佣金提现均为本地模拟，不代表真实外部交易结果。

## 5. 关键端到端验收

1. 后台创建 SPU/SKU、配置规格/库存/价格/会员价、关联分类与配送模板并上架；小程序能浏览并查看详情。
2. 小程序切换 SKU、数量、地址和优惠；展示正确库存、会员价格、运费、优惠明细及应付金额。
3. 模拟下单支付后，后台可查订单、录入物流；小程序看到相同订单状态和物流轨迹，并能确认收货。
4. 确认收货后出现待评价；评价含图片，商家回复后前台可见。
5. 用户申请部分退款或退货退款；后台审核、查看退货物流、验收后，退款金额、库存、积分与佣金调整一致。
6. 不同会员等级下验证等级折扣、SKU 会员价优先规则、积分倍率和生日券有效期/年度去重。
7. 使用分享码建立首次直推关系；再次访问其他推广链接不得覆盖；下单仅给直接推广人生成对应费率佣金。
8. 佣金按商品净额计提、不含运费；确认收货后冻结 7 天；退款冲减，提现在原型内模拟审核和结果记录。
9. 运营维护配送模板、营销活动、协议和会员规则后，小程序读取同一份演示数据并展示更新。

## 6. 非目标与生产化差距

- 本原型不提供真实服务端认证、RBAC 执行、数据库事务、并发库存保护或可靠消息系统。
- 本原型不连接微信支付/退款、物流查询/电子面单、微信原生客服会话或真实提现通道。
- 本原型不提供正式财务对账、法律合规审核、真实账号注销、短信/实名验证或生产级风控。
- 生产化前需依据 `docs/architecture.md` 完成 API 契约、持久化模型、鉴权审计、幂等事务、外部 Provider、对账、安全及部署设计。

- 若原始需求材料重新找到，应优先比对并补充其原始约束；不得将本重建文档标记为原始文件恢复。
- 生产架构文档与原型需求可能存在不同业务假设。例如架构文档包含最多三级分销的通用方案，而 V3 原型经确认采用一级直推；实施时须以目标阶段已确认的业务决策为准，并同步更新冲突文档。
